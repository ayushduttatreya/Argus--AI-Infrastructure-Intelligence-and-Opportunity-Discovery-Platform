# ARGUS Requirements Traceability Matrix (v2 - Hardened Baseline)

This document formalizes the engineering requirements locked for the ARGUS platform following Phase 0.6 contract hardening.

| Requirement ID | Title | Description & Acceptance Condition | Phase Target | Verification Method |
|---|---|---|---|---|
| **ARG-01** | Real Source Ingestion | Connectors must query live third-party APIs (GitHub, Product Hunt, arXiv). Acceptance: At least three live connectors operational with rate-limit and error handling. Empty arrays valid on no results; zero mock records. | Phase 3 | Live integration test verifying HTTP calls to real APIs with live payload assertions |
| **ARG-02** | Eight Agent Capabilities | All 8 specialist agents defined in `agent_definitions`, registered with unique virtual keys, and executable within Temporal workflow activities. | Phase 2 & 5 | Automated registration suite and isolated agent unit tests |
| **ARG-03** | Zero Dummy Data | Production code paths must never inject placeholder companies or synthetic confidence defaults (e.g. removed 0.850 default). Acceptance: All scores calculated deterministically or marked NULL. | Phase 0–6 | Static analysis / AST assertions and contract unit tests |
| **ARG-04** | Verifiable Evidence Provenance | Every factual claim in an intelligence report must link to one or more `evidence_spans` via `claim_evidence` storing verbatim `quote_text`, character offsets `[start, end]`, and `support_type` (supports/refutes). | Phase 4 & 5 | Provenance validation schema checking 100% of claims with text substring match |
| **ARG-05** | Durable Execution & Claim-Check | Missions managed via Temporal workflows. Activities store large raw documents in MinIO and return only lightweight IDs (<20 KB). Reliable dispatch guaranteed by database `workflow_outbox`. | Phase 2 | Worker fault-injection test killing a worker mid-execution and verifying recovery |
| **ARG-06** | Model Isolation & Budgets | Each of the 8 agents authenticates via distinct LiteLLM virtual keys backed by PostgreSQL persistence for hard spend budgets, RPM limits, and explicit model allowlists. | Phase 2 | LiteLLM budget enforcement and model routing tests |
| **ARG-07** | Model Routing Policy | Configurable provider and model selection (fast extraction vs. deep reasoning) with automated fallback to secondary providers without retry multiplication. | Phase 2 | Mock provider timeout test triggering fallback route |
| **ARG-08** | Hybrid RAG & Vector Versioning | Knowledge retrieval combines pgvector 0.8.0+ dense cosine similarity (using `strict_order` or `relaxed_order` iterative scans) with PostgreSQL full-text search (RRF fusion). Embeddings explicitly record model ID and version. | Phase 4 | RAG benchmark testing citation fidelity, iterative scan execution, and recall |
| **ARG-09** | Semantic Caching | Tenant-isolated, freshness-aware, and version-aware cache backed by Redis to prevent redundant LLM inference without serving stale data. | Phase 6 | Cache hit-rate and invalidation test upon new evidence ingestion |
| **ARG-10** | OIDC Authentication | User authentication via Keycloak or standard OIDC provider using Authorization Code + PKCE. Local development supported via `DevAuthProvider` for rapid iteration. | Phase 1 | OIDC token exchange and validation tests |
| **ARG-11** | Authorization, RBAC & Structural RLS | Strict RBAC (Admin, Researcher, Viewer, Service). Multi-tenancy enforced structurally via composite foreign keys `(org_id, id)` across all tables and PostgreSQL RLS with NOBYPASSRLS app role. | Phase 1 | Cross-tenant insertion and query tests verifying RLS and foreign-key rejection |
| **ARG-12** | Runtime Guardrails & SSRF Defense | Strict tool allowlists per agent. Connectors enforce outbound SSRF egress validation (DNS resolution, private subnet blocking, redirect validation). Delimiter framing against prompt injection. | Phase 2 & 3 | Security unit tests against loopback (`127.0.0.1`), metadata IP (`169.254.169.254`), and injection |
| **ARG-13** | End-to-End Observability & Auditing | Level 1 execution auditing in SQL (`prompt_versions`, `model_calls`, `tool_calls`, `mission_events`). Distributed tracing with OpenTelemetry GenAI semantic conventions and Langfuse. | Phase 1 & 2 | Trace propagation verification from HTTP request down to tool execution |
| **ARG-14** | Automated Evaluation | Deterministic schema/tool validation on every run; offline evaluation datasets using Ragas for context recall and claim faithfulness recorded in `evaluation_runs` and `evaluation_results`. | Phase 6 | Automated evaluation pipeline running against golden benchmark datasets |
| **ARG-15** | Versioned API Contracts & Replay | OpenAPI 3.1 contracts with mandatory `Idempotency-Key` header scoped by org, request fingerprinting, replay on duplicate submissions, 409 on conflicts, and monotonic integer SSE reconnection. | Phase 0 & 1 | OpenAPI schema linting and idempotent POST submission tests |
